# 四、决策支持系统与真实应用

## （一）系统建设目标与总体架构

### 1. 建设目标

本系统的建设目标是将前文构建的绿色算力承载能力评估模型工程化封装为可交互、可查询、可追溯的智能决策平台。具体包括三个层次：

**数据服务层**：将 2016-2024 年 31 省 7 维 34 指标的 NAT_FINAL 数据底座转化为结构化查询接口，支持综合得分、排名、七维得分、布局类型、LPA 类型、LISA 空间特征等 20 余种精确查询。

**分析引擎层**：将熵权-CRITIC-TOPSIS 综合评价、潜在剖面分析（LPA）、Global Moran's I 与 LISA 空间分析、障碍度诊断、SHAP 代理模型解释、V2A 布局规则等核心模型封装为可调用的分析模块，对外提供统一接口。

**交互应用层**：面向政府部门、数据中心企业和能源规划机构三类用户，提供可视化仪表盘、自然语言智能问答、企划书可行性分析三种交互方式，降低模型使用门槛。

### 2. 总体架构

系统采用分层可插拔架构，自上而下分为五层：

**展示层**：基于 Streamlit 的 6 页交互式仪表盘（系统总览、省份诊断、多省对比、空间分析、布局决策、智能问答），使用 Plotly 动态图表和 `st.navigation` 原生多页路由。配色采用政府门户蓝（#1E40AF）与可持续能源绿（#059669）的莫兰迪风格。

**智能问答层**：ChatEngine 编排引擎实现"问题分类→混合检索→RAG 提示构建→LLM 生成→数值证据验证"的完整链路。支持数据查询、趋势分析、选址推荐和企划书咨询四种问答模式。

**检索引擎层**：HybridSearcher 实现 PostgreSQL 结构化查询 + ChromaDB 向量语义搜索的双通道混合检索。结构化通道通过关键词正则匹配（10 种查询模式）自动映射至 20+ SQL 查询方法；向量通道以 Qwen text-embedding-v3（1024 维）对企划书 PDF 分块做语义检索。两通道结果经 RRF（Reciprocal Rank Fusion，k=60）融合排序：$$\text{RRF}(d) = \sum_{c \in C} \frac{1}{k + \text{rank}_c(d)}$$，其中 $C$ 为通道集合，$\text{rank}_c(d)$ 为文档 $d$ 在通道 $c$ 中的排名位置。融合后可选择 LLM Reranker 进行精排（0-1 打分）。当无关键词匹配时，系统自动返回 Top10 排名+五类布局汇总+边界省份作为兜底上下文，确保推荐类泛问也能获得充分的数据支撑。

**数据与模型层**：DatabaseManager 管理 PostgreSQL 连接池，QueryEngine 封装 20+ 纯 SQL 查询方法；可插拔 Provider 层统一管理 LLM（DeepSeek/OpenAI）、Embedding（Qwen）、Reranker 和 WebSearch 的创建与切换。

**基础设施层**：PostgreSQL 18 存储 68 张数据表，ChromaDB 存储企划书 PDF 向量，YAML 配置支持 `${ENV:default}` 环境变量替换实现 API Key 不入库。

系统还暴露 4 个标准化 MCP（Model Context Protocol）Server，共 17 个工具（data_query 8 工具/search 3 工具/review 3 工具/ingestion 3 工具），通过 stdio transport 供 Claude Desktop、GitHub Copilot 等 AI 客户端直接调用。

MCP 工具清单：`list_provinces`（31 省列表）、`query_province_score`（省得分/排名/布局/LPA）、`compare_provinces`（多省对比）、`get_trend`（历年趋势）、`query_layout`（五类布局查询）、`get_dimensions`（七维得分）、`get_boundary_provinces`（边界省份）、`get_ranking`（Top N 排名）、`search`/`search_db`/`search_web`（混合/结构化/联网检索）、`ingest_document`/`list_documents`/`delete_document`（PDF 摄入管线）、`generate_report`/`review_report`/`auto_revise`（报告生成与 MiniMax 评审）。

## （二）数据—模型—系统一致性闭环

系统设计了严格的一致性保障机制，确保工程化实现与论文模型分析结果完全一致。

**Golden Set 驱动**：以 `01_系统标准答案_Golden_Set.xlsx`（31 省 × 17 字段）为唯一标准答案，所有查询输出必须与之完全匹配。系统内置 GoldenSetValidator，对 527 个断言（31 省 × 17 字段）进行自动化差分检测。

**数值零幻觉机制**：ChatEngine 在 LLM 生成回答后执行 `_extract_evidence` 后验证——提取回答中所有浮点数，与检索结果原文逐一对照，标记"孤儿数字"（未在检索结果中找到来源的数字）并追加警告。系统提示词强制要求"所有数值来自检索结果，不得编造，严禁自行推断"。

**术语口径统一**：系统内术语与前文论文模型严格对应，映射关系如下：

| 论文模型术语 | 系统展示术语 | 统一原因 |
|------------|------------|---------|
| LISA 局部空间自相关 | "探索性局部空间证据" | FDR 校正后无显著省份 |
| SHAP 特征重要性 | "代理模型一致性检验" | XGBoost 逼近 TOPSIS，非因果推断 |
| LPA 潜在剖面分析 | "基于多期得分轨迹的潜在类别识别" | 统计聚类，非确定型分类 |
| 国家枢纽节点 | "政策一致性" | X34 已进入指标体系，非独立外验 |
| 未来趋势推断 | "基于2016-2024历史数据的趋势研判" | 不做精确数值预测 |

此外，ChatEngine 的 `_classify` 模块采用正则匹配进行城市级越界检测（仅拦截明确指定"城市名+市"的精确排名查询，不含趋势/推荐/对比类泛问），将越界请求引导向省级评估。

**数据版本冻结**：所有数据和查询结果标注"NAT_FINAL"版本标识，确保系统输出可追溯至具体的 Excel 源文件和数据库表。

**回溯验证**：内置 10 道标准问题的 QA 质量评估集，覆盖数据查询、趋势分析、选址推荐、越界拒绝四类场景，自动检测数值准确率、术语合规率和证据可追溯率。

## （三）政府场景：省域短板诊断与分类治理

系统为政府部门提供三类典型应用场景：

**区域监测**：在"系统总览"页，可一键查看 31 省 KPI 卡片（评估省份数、数据年份、排名第一省份、高适宜承载区数量、边界省份数量）、综合得分排名棒棒糖图和五类布局旭日图，快速把握全国绿色算力发展格局。

**省域诊断**：在"省份诊断"页，选择目标省份后系统展示综合得分、全国排名、V2A 布局类型、LPA 发展类型和稳定性标签 6 项核心指标，配合七维雷达图（动态范围自适应）和历年趋势面积图。若该省为边界型省份（Bootstrap 保持率 < 80%），系统自动触发橙色警告，提示决策风险。

**分类治理**：在"布局决策"页，系统按 V2A 五类布局展示各省归属、平均得分、绿色数据中心数量和枢纽节点信息。勾选特定布局类型后，可下钻查看各省综合得分、排名、LPA 类型和稳定性标签。边界省份列表独立呈现，标注 Bootstrap 保持率。

**空间分析**：系统提供 Global Moran's I 历年趋势（含 5%/10% 显著性标注）、中国省级 Choropleth 填充地图（综合得分着色）和 2024 年 LISA 局部空间分析。LISA 结果标明"经 BH-FDR 多重比较校正后所有省份均不显著，仅作探索性参考"。

## （四）企业场景：候选省份筛选与任务匹配

系统面向数据中心企业提供"自然语言选址推荐"能力，体现在三个层面：

**需求拆解**：当用户输入"哪个省份适合建 AI 训练中心？""适合建大型车厂？"等问题时，ChatEngine 自动将模糊需求转化为维度侧重——AI 训练中心侧重数字基础设施+创新人才+气候条件，车厂侧重能源供给+需求基础+低碳约束，大型数据中心侧重能源供给+气候条件+低碳约束。

**量化匹配**：系统检索 31 省综合得分、七维得分、布局类型和 LPA 稳定性数据，按需求维度排序，输出 Top 3-5 推荐省份，每省附带量化依据（得分、排名、匹配理由）和风险提示（LPA 稳定性、边界省份、人才短板）。

**企划书可行性分析**：企业上传 PDF 企划书后，系统自动执行"解析→分块→向量化→入库"的摄入管线，然后结合 NAT_FINAL 省级数据、企划书提取的关键参数（IT 负载、PUE、绿电比例、业务类型等）和 ChromaDB 向量语义搜索，提供逐维匹配分析和匹配度星级评分（☆ 1-5）。系统还会建议 2-3 个替代省份并提示选址风险。

## （五）自然语言智能问答与结果追溯

智能问答是本系统的核心技术难点和能力亮点。

**问答流程**：用户输入自然语言问题→ChatEngine 分类（通过城市级越界检测）→HybridSearcher 双通道检索（PostgreSQL 结构化查询 + ChromaDB 向量语义搜索）→构建 RAG 提示词（系统提示词 + 检索结果上下文 + 用户问题）→LLM 生成回答→`_extract_evidence` 数值来源验证→返回回答附证据引用。

**多类型问题支持**：系统不是简单的查表工具，而是能够进行数据查询（"江苏 2024 年综合得分？"）、对比分析（"内蒙古和浙江对比"）、趋势研判（"哪些省份有发展潜力？"）和选址推荐（"适合建数据中心？"）的智能决策助手。系统不拒绝"未来趋势""选址建议"类问题，而是引导 LLM 基于历史数据做研判，不做精确数值预测。

**证据追溯**：每个回答附带的"数据来源"模块列出引用的数据库表和向量文档片段。回答中的每个数字都可追溯到具体的检索结果原文，实现"可解释、可追溯"的决策支持。

**企划书双通道检索**：企划书咨询模式下，HybridSearcher 同时检索 PostgreSQL（NAT_FINAL 省级数据）和 ChromaDB（企划书 PDF 向量），通过 RRF 融合排序，确保回答既基于全国数据对比，又参考企划书原文。

## （六）部署环境、测试框架与可复现性边界

### 1. 技术栈与部署

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端 | Streamlit + Plotly + CSS | `st.navigation` 原生多页，Choroplethmapbox 中国地图 |
| 后端 | Python 3.10+ | ChatEngine + HybridSearcher + 4 MCP Servers |
| 数据库 | PostgreSQL + ChromaDB | 68 张结构化表 + 向量知识库 |
| LLM | DeepSeek / OpenAI（OpenAI SDK 统一接口） | 可插拔 Provider，改配置即可切换 |
| Embedding | Qwen text-embedding-v3（1024维） | 企划书 PDF 向量化 |
| 配置 | YAML + `${ENV:default}` | API Key 不入库 |
| MCP | mcp >= 1.0, stdio transport | 4 Server × 17 Tools |

系统最低硬件要求：4 核 CPU、16 GB RAM、50 GB 磁盘。PostgreSQL 需预先导入 NAT_FINAL 数据。

### 2. 测试框架

**Golden Set 回归测试**：`GoldenSetValidator` 对 31 省 × 17 字段的 Golden Set 逐一校验，确保系统输出与 Excel 标准答案完全一致。

**QA 质量评估**：10 道标准问题自动测试集（含数据查询、对比分析、趋势研判、选址推荐和越界拒绝五类场景），经实际运行验证，10/10 答案中所有数值均能在 Golden Set 或检索结果中找到原文对照，术语均符合统一口径规范（LISA/SHAP/LPA 无禁用表述），每答案均附来源标注，越界问题（如城市级排名查询）均被正确拒绝。

**系统完整性检查**：`python main.py evaluate` 一键运行数据库连接（6 表行数校验）→数据完整性（Golden Set 527 断言）→模块导入（40 模块）→API Key（3 密钥配置检查）→提示词（8 强制术语校验）→MCP 工具（17 工具注册检查）→Dashboard（6 页+9 图表+配置完整性）的 7 项全链路检查。

### 3. 可复现性边界

系统采用 NAT_FINAL 数据冻结版本，所有模型参数（熵权-CRITIC 权重、LPA 拟合参数、V2A 规则阈值、Monte Carlo 扰动参数）在系统中保持不变。数据库查询走纯 SQL（`QueryEngine`），不依赖 ORM 自动推断，确保每次查询结果可精确复现。系统配置通过 `config/settings.yaml` 集中管理，克隆仓库后执行 `python main.py setup` 即可重建完整环境。

## （七）局限性与适用范围

系统当前存在以下边界：（1）仅支持省级评估，不适用于城市级、区县级和园区级分析；（2）依赖 NAT_FINAL 静态数据集，不支持实时数据接入和动态更新；（3）选址推荐和可行性分析为决策参考而非替代专业的可行性研究报告；（4）LLM 生成内容虽经数值幻觉检测，但在极端边缘场景下仍可能出现语义层面的不准确，建议关键决策时交叉验证。本系统的主要贡献定位于工程整合创新——将前文的评价模型、空间分析和布局规则统一封装为端到端决策支持系统，并设计了一套数字溯源与术语统一的一致性保障机制，而非在算法层面提出新方法。

## （八）社会效益与经济价值机制

**提升政府决策效率**：将 7 维 34 指标的复杂评估模型封装为一键查询的交互式仪表盘，政府部门无需掌握统计方法即可进行省域监测和分类治理，相比传统人工调取 Excel 数据后分析制图的工作流程，信息获取延迟从小时级降至秒级。

**降低企业选址成本**：企业无需另行委托咨询机构进行可行性分析，通过智能问答和企划书分析功能即可获得基于全国省级数据的量化选址建议，显著缩短选址调研和方案对比周期。

**推动绿色算力生态建设**：系统内置的 V2A 布局规则、边界省份预警和 LPA 稳定性信息，引导算力布局从"单一排名优先"转向"综合承载能力+稳定性+绿色低碳约束"并重的科学决策模式。

**促进产学研一体化**：系统作为论文模型的工程化落地载体，验证了"评价模型→决策系统→真实应用"的完整闭环，为后续相关研究提供了可复现、可扩展的技术框架。系统已开源至 GitHub（https://github.com/Evil-Bubble-wzx/green-computing-competition），支持二次开发和定制化部署。
